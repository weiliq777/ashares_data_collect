# 回测数据集按时间组合

## 目的

历史 `FROZEN`（已冻结）物化数据集保持原样。增加新日期时，只构建并冻结新增日期的物化分段，再创建一个 `COMPOSITE`（组合）数据集作为只保存引用的逻辑视图；不复制历史行情、快照、血缘或基准事实行。

```text
历史物化 Dataset（冻结） ─┐
                           ├─ COMPOSITE Manifest（仅引用、哈希与日期范围）
新增日期物化 Dataset（冻结）┘
```

组合按 SSE 开市日切分，每个开市日只能归属一个组件；分段必须连续、无重叠。新增物化分段可以采用更新的数据基线，但策略字段、价格口径、日历/市场/费用规则版本、基准和字段可见性契约必须与历史组件兼容。增量分段可以包含计算指标所需的预热日期，但组合只把历史末日之后的新评估日期归给它。

## 安全边界

- `COMPOSITE` 创建和验收只查询组件 Manifest、质量证明、基线元数据及有界交易日历，不扫描股票行情/快照事实大表。
- 组合数据集不执行物化 `build`；其质量证明继承已冻结物化组件的验证结果，并对组件身份和日期覆盖重新校验。
- 正式回测仍会读取实际评估区间所需的行情和快照，但按日期窗口、keyset 分页与有限缓存读取；这是回测计算本身，不是再次复制或全量重建数据集。
- `execution_page` 仅用于物化数据集的逐行哈希校验，对组合数据集 fail-closed，避免误做跨组件全历史事实重扫。
- 组件上限为 128。日常增量建议按月或季度形成分段；接近上限时应重新评估分层清单方案，不能默默突破。
- SQL 迁移 `108_backtest_dataset_composition.sql` 必须先在目标环境按既有迁移流程执行。本实现不自动迁移数据库。

## 操作顺序

1. 用最新已验证基线，仅对新增日期构建普通物化 Dataset；按原流程执行 `build`、`validate`、`freeze`。
2. 组合历史冻结数据集与新增冻结数据集。已有组合可作为第一个输入，后续输入必须是新的冻结物化分段：

```powershell
python -m data_collect.jobs.backtest_dataset compose `
  --component-dataset-id <历史冻结Dataset或历史组合ID> `
  --component-dataset-id <新增日期冻结DatasetID> `
  --name strategy-data-through-2026-09 `
  --version 1
```

3. 对命令输出的组合 ID 执行 `validate`，再按项目现有冻结流程执行 `freeze`。组合冻结前不会被正式回测接受。
4. 正式回测把组合 Dataset ID 当普通冻结 Dataset 使用；策略、Scenario 和旧组件均不改写。

固定 `--dataset-id` 仅用于恢复同一个 DRAFT 创建尝试；恢复时清单、代码身份与已有组件必须是原意图的精确匹配前缀，否则拒绝继续。

## 当前实现范围

已经实现代码、测试和迁移脚本；尚未在生产数据库执行迁移、创建增量物化分段或组合数据集，也未启动回测。首次真实使用前还需在目标 PostgreSQL 执行迁移，并先完成一个小日期窗口的物化分段与组合验收。
