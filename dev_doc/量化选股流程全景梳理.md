# 量化选股流程全景梳理（含术语中文说明）

> 本文梳理 `Finance_cn / ashares_data_collect` 当前从"原始数据"到"最终买入候选"的完整
> 流程能力：每一层如何过滤、过滤规则是什么、涉及哪些专有名词。
> 所有英文缩写均附带中文说明，方便非量化背景阅读。
> 更新日期：2026-08-16（基于当前代码库现状梳理）

---

## 0. 系统总体定位

本系统是一套 **A 股多因子量化选股 + 回测验证 + 人工确认交易** 的个人研究平台：

- **数据源**：Tushare（主力）、QMT/xtquant、东财/同花顺/新浪等
- **存储**：PostgreSQL（结构化数据）
- **核心目标**：在约 5000+ 只 A 股中，通过**层层过滤**，找到"未来上涨概率较大"的股票，
  输出**候选清单（candidates）**，经 **AI 反方审计 + 人工拍板** 后模拟成交（纸面组合），
  全程不自动连接券商、不自动下单。

整条链路可概括为一条**漏斗**：

```
全市场股票（约 5000+ 只）
  │  第 1 层：股票池过滤（市场板块 / 上市状态 / ST）
  ▼
可投资股票池（Universe）
  │  第 2 层：当日可交易过滤（停牌 / 涨跌停 / 可买可卖）
  ▼
当日可交易股票
  │  第 3 层：数据质量过滤（各数据源必须 VALID）
  ▼
数据可信股票
  │  第 4 层：策略信号过滤（估值 / 基本面 / 趋势 / 量能）
  ▼
买入信号（BUY signals）
  │  第 5 层：风险与仓位过滤（单笔风险 / 单仓上限 / 现金 / 流动性）
  ▼
可执行候选（eligible candidates，含计划股数、止损价）
  │  第 6 层：AI 反方审计 + 人工决策
  ▼
人工批准 → 纸面组合模拟成交（Paper Portfolio）
```

下面按层详细展开。

---

## 1. 第 0 层：数据采集与加工（不是过滤，但决定过滤的"原料"）

所有过滤都建立在高质量数据之上。数据链路严格遵循"防未来函数"原则
（PIT，Point-In-Time，时点可见性——即某一天做决策时，只能使用**那一天之前已经公开**的数据，
绝不能用未来才知道的财报/复权数据回看历史）：

```text
Tushare 原始接口
   → Raw 原始表（tushare_*_raw_version，不可变、可断点续传）
   → Standard 标准化表（daily_kline、stock_basic_info 等）
   → PIT 时点层（pit.universe_daily 股票池 / pit.security_tradeability_daily 可交易性）
   → Feature 特征层（feature.price_daily_v2 价格特征 / feature.valuation_daily_v1 估值特征 /
                     feature.company_financial_v1 财务特征）
   → Research Snapshot（research.stock_snapshot_daily 冻结快照）
```

关键执行文件：

| 环节 | 文件 | 作用 |
|---|---|---|
| 每日行情增量 | `jobs/tushare_market_incremental_by_date.py` | 按交易日全市场拉取日线/估值/复权因子 |
| 财务增量 | `jobs/tushare_financial_vip_incremental.py` | 财务报表与指标增量 |
| Standard 重建 | `jobs/tushare_phase2_standard.py` | 生成股票池、可交易性、涨跌停状态 |
| Feature 计算 | `jobs/tushare_phase2_features.py` | 计算均线、量比、PE 分位等指标 |
| 快照生成 | `jobs/research_snapshot.py` | 把当日所有指标冻结成不可变快照 |

**为什么先冻结快照再过滤？**
因为回测/决策必须可复现：`research.stock_snapshot_daily` 每个交易日存一份**只读冻结**的
全市场截面数据（FROZEN 状态），之后所有策略过滤只读这份快照，不再查实时表，保证
"同样的输入必然得到同样的结果"。

## 2. 第 1 层：股票池过滤（Universe，硬性排除）

数据表：`pit.universe_daily`（构建于 `tushare_phase2_standard.py::rebuild_universe`）

把全市场股票缩到"系统愿意研究"的范围内。规则（SQL 可见）：

| 字段 | 规则 | 中文解释 |
|---|---|---|
| `eligible_by_market` | 市场 ∈ {主板, 创业板, 科创板, 北交所} | 只研究四大主流板块；剔除新三板、B 股、退市整理等无法按常规规则交易的品种 |
| `is_listed_asof` | 当日已上市 | 排除尚未上市（未来上市）的股票 |
| `is_st_asof` | 剔除 ST | 排除被特别处理的股票（ST = Special Treatment，因连续亏损/违规等被交易所特别处理，涨跌幅限制收窄、风险高） |
| `has_price_history` | 当日有行情记录 | 排除完全没有价格数据的股票 |

不符合的股票记录 `exclusion_reason`（排除原因），如 `MARKET`（板块不符）、`ST`、`NOT_LISTED`。

**这是第一道"粗筛"，通常会把全市场 5000+ 只缩到约 4000+ 只。**

---

## 3. 第 2 层：当日可交易过滤（Tradeability）

数据表：`pit.security_tradeability_daily`（构建于 `tushare_phase2_standard.py::rebuild_tradeability`）

即使股票在股票池里，某一天也可能**买不进或卖不出**。规则：

| 字段 | 规则 | 中文解释 |
|---|---|---|
| `is_tradeable` | 当日非停牌、非异常状态 | 停牌（Suspended）= 当日无交易，一切信号无效 |
| `can_buy` | `is_tradeable` 且非**涨停** | 涨停（UP_LIMIT）= 当日封在涨停板，买单排队买不进；只有非涨停才能买 |
| `can_sell` | `is_tradeable` 且非**跌停** | 跌停（DOWN_LIMIT）= 当日封在跌停板，卖单排队卖不出 |
| `limit_status` | 记录当日涨跌停状态 | 用于解释为什么被拦 |

涨跌停价来自 `std.security_status_daily`（Tushare `stk_limit` 接口的涨跌停价）。
这条过滤的意义：**策略可以选出"看起来好"的股票，但如果当天买不进，一切白搭。**

---

## 4. 第 3 层：数据质量过滤（Quality Gate，防垃圾进决策）

数据表：`research.stock_snapshot_daily.quality_status`

快照把 6 个数据源的质量状态合并成一个综合标记（合并规则见 `research_snapshot.py`）：

- 任一源 `MISSING_SOURCE`（缺源）→ 整条 `MISSING_SOURCE`
- 任一源 `WARNING`（有警示）→ 整条 `WARNING`
- 全部 `VALID` → 整条 `VALID`

在候选生成时（`candidate_service.py`）与观察池生成时（`research_watchlist.py`）均要求：
`quality_status NOT IN ('MISSING_SOURCE', 'INVALID')`。

**解释**：这一层防止"指标算出来但底层数据残缺/可疑"的股票混进决策。比如某股票
MA20（20 日均线）因为缺了 3 天行情而算错，质量标记就会是 WARNING，直接拦截。

## 5. 第 4 层：策略信号过滤（核心选股逻辑）

这是**最核心**的一层，位于 `data_collect/backtest/engine.py`。
系统有两套策略，日常候选默认使用 **v2 策略**：

### 5.1 v1 策略（value_trend_v1，估值安全边际 + 均线趋势）

第一版确定性示例策略（`ValueTrendStrategy`），保留用于历史兼容。硬性过滤条件：

| # | 条件 | 中文解释 |
|---|---|---|
| 1 | `is_listed_asof = True` | 已上市 |
| 2 | `eligible_by_market = True` | 板块合格 |
| 3 | 非 ST（或显式允许 ST） | 排除风险股 |
| 4 | `pe_pct_5y ≤ 0.30` | **PE 5 年分位数**（当前市盈率在近 5 年估值区间中的百分位）≤ 30%，即"当前估值处于近 5 年较便宜区间" |
| 5 | `is_pe_meaningful = True` | PE 有意义（排除亏损导致 PE 为负/失真） |
| 6 | 收盘价 > MA20 > MA60 | **MA20（20 日均线）= 最近 20 个交易日收盘价的平均值**；MA60（60 日均线）同理。要求"收盘价站在 20 日线上方，且 20 日线在 60 日线上方"= 中期趋势向上（均线多头排列） |
| 7 | `volume_ratio_20d ≥ 1.0` | **量比（20 日）= 当日成交量 ÷ 近 20 日平均成交量**。≥1.0 表示当日放量，量能配合 |

打分（只影响同一天多个候选的**资金优先级**，不改变硬过滤）：
`信号分 = 估值分 + 趋势分 + 量能分`，分数越高，资金越优先买它。

### 5.2 v2 策略（fundamental_value_growth_trend_v2，正式版：成熟样本 + 基本面双轨 + 趋势触发）

日常候选默认策略（`FundamentalValueGrowthTrendStrategy`，strategy_id =
`fundamental_value_growth_trend_v2`）。在 v1 基础上大幅强化基本面要求，分三层：

**第一层：通用硬过滤（所有股票必须满足）**

| # | 条件 | 中文解释 |
|---|---|---|
| 1 | `is_listed_asof` / `eligible_by_market` | 上市 + 板块合格 |
| 2 | 非 ST | 排除风险股 |
| 3 | `ma20_observation_count ≥ 20` 且 `ma60_observation_count ≥ 60` | MA20/MA60 必须由**足量真实交易日**算出（防止新股/数据残缺导致均线失真） |
| 4 | 收盘价 > MA20 > MA60 | 中期趋势向上（同 v1） |
| 5 | `volume_ratio_20d ≥ 1.5` | 量比 ≥ 1.5，要求**更明显的放量**（v1 只需 1.0） |
| 6 | `debt_to_assets < 50` | **资产负债率 < 50%**：总负债 ÷ 总资产 < 50%，排除高杠杆公司 |

**第二层：基本面"双轨"（二选一满足即可）**

- **轨道 A：价值质量轨（traditional，传统价值股）**——要求**同时**满足：
  - `has_full_pe_5y_history = True` 且 `valuation_observation_count ≥ 1000`：有完整近 5 年估值历史（约 1000+ 个交易日）
  - `is_pe_meaningful = True`：PE 有意义（非亏损）
  - `pe_pct_5y ≤ 0.30`：当前 PE 处于近 5 年 ≤30% 分位（估值便宜）
  - `annual_report_count_5y = 5`：近 5 年年报齐全
  - `roe_5y_all_above_15 = True` 且 `roe_5y_min > 15`：**ROE（净资产收益率 = 净利润 ÷ 净资产，衡量公司赚钱能力）近 5 年每年都 > 15%**，且最低一年也 > 15%
  - `ocf_report_count_3y = 3` 且 `ocf_3y_all_positive = True`：**OCF（经营现金流）近 3 年每年均为正**（利润是"真金白银"而非纸面利润）

- **轨道 B：成长质量轨（growth，高成长股）**——要求**同时**满足：
  - `list_date` 距今 ≥ 2 年（`min_listing_days = 365*2`）：上市满 2 年（排除次新股炒作）
  - `quarterly_report_count_4q = 4`：近 4 个季度财报齐全
  - `q_sales_yoy_4q_all_above_30 = True` 且 `q_sales_yoy_above_30_quarters_4q = 4`：
    **连续 4 个季度营收同比增速（q_sales_yoy = 单季营业收入同比增长率）都 > 30%**
  - `debt_to_assets < 50`（继承第一层）

**第三层：信号打分与止损绑定**

```
信号分 = 估值分(0~1) + 趋势分(收盘价/MA20 - 1) + 量能分(量比) + 轨道加成(价值 0.20 / 成长 0.15)
止损价 = 当日收盘价 × (1 - 8%)   （8% = stop_loss_pct）
```

**关键点**：v2 的双轨设计理念 = "**又便宜又好**"（价值轨：低估值 + 高 ROE + 正现金流）
或 "**长得又快又稳**"（成长轨：连续 4 季高增长 + 低负债），并且都要叠加"**趋势向上 +
放量**"的技术面确认，这就是"上涨概率较大"的核心依据。

### 5.3 卖出信号（同一层逻辑的一部分）

对**已持有**的股票（`generate_signals` 中先判断持仓）：

- 若收盘价跌破 MA20（20 日均线）→ 生成 **SELL（卖出）信号**，规则名 `close_below_ma20`
- 否则不再重复发 BUY

**止损保护**：每笔买入成交即绑定固定止损价（买入价下方 8%），跌破止损触发卖出
（回测引擎中"止损优先于策略卖出"）。

## 6. 第 5 层：风险与仓位过滤（能买多少？买得起吗？）

信号层只回答"**想买谁**"，这一层回答"**买多少、买不买得起、会不会把账户风险搞爆**"。
代码在 `data_collect/backtest/risk.py`，由 `candidate_service.py::create_candidate_run` 执行。

### 6.1 资金与组合约束（默认参数）

| 参数 | 默认值 | 中文解释 |
|---|---|---|
| `initial_cash` | 10,000 元 | 组合初始资金 |
| `risk_pct` | 1% | **单笔风险预算**：每笔买入最多承受总资金 1% 的损失 |
| `max_portfolio_risk_pct` | 3% | **组合总风险上限**：所有持仓的潜在损失合计不超过总资金 3% |
| `max_single_position_pct` | 25% | 单只股票市值不超过总权益的 25% |
| `reserve_cash_pct` | 10% | 预留现金比例（永远留 10% 现金不动） |

### 6.2 仓位计算（size_position，风险平价定仓）

买入数量不是"想买多少买多少"，而是按**风险预算倒推**：

1. 计算压力买入价 = 买入价 + 滑点（**滑点 slippage** = 实际成交价与预期价的偏差，默认 10 个基点 bps，1 bps = 万分之一）
2. 计算压力卖出价 = 止损价 - 滑点
3. 每股压力损失 = (压力买入价 - 压力卖出价) + 跳空压力（**gap stress** = 隔夜跳空风险，默认 5%）
4. 理论股数 = 单笔风险预算 ÷ 每股压力损失
5. 向下取整到整手（100 股/手，`min_buy_lot = 100`）
6. 再受三重上限约束：可用现金、单仓 25% 上限、组合剩余风险预算

**结果含义**：`required_capital`（所需资金）、`max_loss_at_stop`（止损最大损失）、
`actual_risk_pct`（实际风险比例）都会算出来并记录到候选里。

### 6.3 流动性门禁（check_liquidity，整笔拒单）

任何候选在确认可执行前，必须通过**成交量检查**：

| 检查项 | 规则 | 中文解释 |
|---|---|---|
| 成交量缺失/为零 | 拒绝 | 无成交量的股票无法成交 |
| 成交额缺失/为零 | 拒绝 | 同上 |
| 单位异常 | 拒绝 | 成交额÷成交量算出的均价不在 [最低价×0.5, 最高价×1.5] 区间 → 怀疑数据单位错误 |
| 容量超限 | 拒绝 | 计划股数 > 当日成交量 × **5% 参与率**（`max_volume_participation_pct = 0.05`）→ **整笔拒绝，不缩量成交**（怕订单太大冲击股价） |

**注意**：流动性检查在候选生成和回测两处都会做，保证"理论上能买"且"实际能买"。

### 6.4 组合级风险预算联动

- 已有持仓会占用组合风险预算（按现有持仓的止损距离估算剩余风险，`open_position_stop_risk`）
- 新买入候选按信号分从高到低**依次消耗**剩余风险和剩余现金
- 预留现金是**固定下限**：可用现金 = 当前现金 - 总权益 × 10%

## 7. 第 6 层：AI 反方审计 + 人工决策（决策安全闸）

候选生成后进入 `research.candidate` / `research.candidate_run` 表，
每个候选附带**不可变的审计数据包（candidate packet）**（`get_candidate_packet`），
包含：快照哈希、参数哈希、组合状态哈希、规则快照哈希、信号分、计划股数、止损价、
最大损失、证据引用等。任何一步输入变化都会导致哈希变化 → 审计对象失效。

### 7.1 AI 审计（skill: `ashares-decision-audit`）

AI 拿到数据包做**反方审计**（挑毛病），输出 `action`（APPROVE/REJECT）+ `risk_level`（风险等级）+ 证据引用。

### 7.2 人工决策门禁（`record_human_decision`）

只有人工才能 APPROVE，且**系统强制校验**：

- 只有系统判定 `eligible = True`（通过了 1~5 层所有过滤）的候选才可批准
- AI 明确 REJECT 或风险等级 HIGH 的候选**禁止批准**
- **BUY 批准必须**：
  - 引用**正方（supporting）+ 反方（contrary）证据**各至少一条
  - 至少 2 个独立数据源交叉验证
  - 至少 1 条官方或内部事实级证据
  - 证据发布时间/生效时间不得晚于研究截止日（防未来函数）
- 一个候选不能重复决策（防覆盖）

### 7.3 纸面组合模拟成交（`data_collect/portfolio/`）

人工批准后生成 `PENDING_APPROVAL` 的交易意图（intent），再经**模拟成交**
（`PaperPortfolioEngine`，只按人工确认的价格/股数成交），更新现金账本与持仓。
**全程不连接券商、不下真实订单**——这是个人研究系统的安全边界。

## 8. 回测验证层（这套规则到底赚不赚钱？）

`data_collect/backtest/` 提供完整的历史回测来验证过滤规则的有效性：

| 组件 | 作用 |
|---|---|
| `jobs/backtest_dataset.py` | 把历史每日冻结快照打包成不可变的回测数据集（Dataset，分 WARMUP 预热区 / EVALUATION 评估区） |
| `backtest/engine.py` | 纯 Python 日线撮合引擎：**T 日收盘出信号 → T+1 开盘成交**，处理涨跌停、停牌、T+1 可卖、除权除息 |
| `backtest/risk.py` | 上述所有风险/仓位/流动性逻辑，与实盘候选**共用同一套代码**（保证回测=实盘逻辑） |
| `jobs/backtest_run.py` | 运行回测并持久化事件账本、绩效 |
| `dev_doc/backtest_rules_approved_v3.yaml` | **已批准的规则文件**：佣金 0.03%、印花税、过户费、滑点 10bps、跳空 5%、成交量参与率 5% 等（按时间区间版本化，防"改规则洗历史业绩"） |

**回测契约关键点**（防自欺）：
- 评估区间（EVALUATION）与预热区间（WARMUP）分离——MA120、PE 5 年分位等需要历史数据的
  指标必须在评估起点之前就"预热"完成，不能用评估期内的数据算
- 信号日收盘价不能当作成交价（T+1 开盘才成交）
- 回测只读冻结 Dataset，运行中不查数据库

## 10. 专有名词速查表（看不懂时先看这里）

| 缩写 | 全称 | 中文解释 |
|---|---|---|
| **MA5/MA20/MA60/MA120** | Moving Average | **均线**：最近 N 个交易日收盘价的平均值。MA20 = 20 日均线（月线级别），MA60 = 60 日均线（季度级别），MA120 = 半年线。MA20 > MA60 常视为中期趋势向上 |
| **PE** | Price-to-Earnings Ratio | **市盈率** = 股价 ÷ 每股收益。衡量"多少年回本"。PE 高 = 贵，PE 低 = 便宜 |
| **PE_TTM** | PE Trailing Twelve Months | 滚动 12 个月市盈率（用最近四个季度加总盈利算的 PE，更实时） |
| **pe_pct_5y** | PE Percentile 5 Years | **PE 近 5 年分位数**：当前 PE 在近 5 年所有 PE 值中排第百分之几。≤30% 表示"当前处于近 5 年 30% 以下的便宜位置" |
| **PB** | Price-to-Book Ratio | **市净率** = 股价 ÷ 每股净资产 |
| **ROE** | Return on Equity | **净资产收益率** = 净利润 ÷ 净资产。衡量公司用股东的钱赚钱的能力，>15% 属优秀 |
| **ROA** | Return on Assets | **总资产收益率** = 净利润 ÷ 总资产 |
| **资产负债率** | Debt-to-Assets | 总负债 ÷ 总资产。越高杠杆越大、越危险 |
| **revenue_yoy / tr_yoy** | Year-over-Year | **同比增速**：营业收入同比 / 营业总收入同比（相比去年同期增长百分之多少） |
| **q_sales_yoy** | Quarterly Sales YoY | 单季营业收入同比增速 |
| **netprofit_yoy** | Net Profit YoY | 净利润同比增速 |
| **OCF** | Operating Cash Flow | **经营现金流**：公司日常经营赚到的真金白银。连续为正说明利润质量高 |
| **ST** | Special Treatment | **特别处理**：因连续亏损/异常被交易所标记的股票，风险高，涨跌幅限制收窄（5%） |
| **量比** | Volume Ratio | 当日成交量 ÷ 近 N 日平均成交量。>1 放量，<1 缩量 |
| **volatility_20d** | 20-day Volatility | 20 日波动率：最近 20 日每日收益率的样本标准差 |
| **涨停/跌停** | Limit Up / Limit Down | 交易所设定的单日最大涨幅/跌幅（主板 ±10%，创业板/科创板 ±20%，ST ±5%） |
| **停牌** | Suspension | 因重大事项等暂停交易，当日无行情 |
| **滑点 bps** | Slippage Basis Points | 实际成交价与预期价的偏差。1 bps = 万分之一，10 bps = 千分之一 |
| **跳空风险** | Gap Risk | 隔夜跳空：今天收盘到明天开盘之间价格直接跳过一段，止损可能无法按计划价成交的风险 |
| **止损** | Stop Loss | 预设的离场价（本系统 = 买入价下方 8%），跌破即卖出，控制单笔最大亏损 |
| **分位** | Percentile | 把历史数据按从小到大排序后，当前值所处的位置（0~1） |
| **PIT** | Point-In-Time | 时点可见性：只用"当天已公开"的数据，防未来函数 |
| **FROZEN Snapshot** | — | 冻结快照：某交易日全市场数据的一次性只读快照，保证决策/回测可复现 |
| **Candidates** | — | 候选：通过层层过滤、待审计的买入/卖出计划（含股数、止损、风险金额） |
| **Eligible** | — | 可执行：通过了系统全部过滤（含风险/仓位/流动性），可以进入人工决策 |

## 11. 一图流：一个候选从出生到成交的完整生命周期

```text
[全市场 ~5000+ 只]
    │
    ▼ 第1层：板块 / 上市 / ST        → 剔除新三板、B股、未上市、ST
[可投资股票池 ~4000+ 只]
    │
    ▼ 第2层：停牌 / 涨跌停 / 可买可卖
[当日可交易股票]
    │
    ▼ 第3层：数据质量 VALID（6 源合并）
[数据可信股票]
    │
    ▼ 第4层：v2 策略硬过滤
    │   ├ 趋势：收盘 > MA20 > MA60
    │   ├ 量能：量比 ≥ 1.5
    │   ├ 负债：资产负债率 < 50%
    │   └ 双轨之一：
    │       ├ 价值轨：PE 5年分位≤30% + 5年ROE均>15% + 3年OCF为正 + 5年数据齐全
    │       └ 成长轨：上市≥2年 + 连续4季营收同比>30%
    ▼
[BUY 信号（含 8% 止损价、信号分排序）]
    │
    ▼ 第5层：风险/仓位/流动性
    │   ├ 单笔风险 1%、组合风险 ≤3%、单仓 ≤25%、预留现金 10%
    │   ├ 风险平价定股数（止损距离倒推）
    │   └ 成交量 5% 参与率整笔门禁
    ▼
[可执行候选 eligible=True]（记录：计划股数/所需资金/最大损失/滑点/跳空压力）
    │
    ▼ 第6层：AI 反方审计（正方+反方证据，≥2 独立来源）
    │         → 人工 APPROVE / REJECT / DEFER（系统强制证据校验）
    ▼
[纸面组合：PENDING_APPROVAL → APPROVED → 模拟成交 → 持仓/现金账本]
    │
    ▼（持仓中）
[跌破 MA20 → SELL 信号；跌破止损 → 强制止损卖出]
```

## 12. 当前能力边界与注意点（诚实说明）

1. **系统当前是"研究+模拟"定位**：只输出候选、只做纸面组合，**不自动下单、不连券商**。
2. **正式回测数据集仍在构建中**（代码已完备，agent.md 记录完整五年 Snapshot/Dataset/Run
   仍是待办；当前存在历史烟测结果，不能当作正式绩效）。
3. **v2 策略规则被代码硬性固定**（ROE>15、季度营收同比>30、PE 分位≤30%、量比≥1.5、
   负债率<50%、止损 8%）——这些阈值是**当前策略版本的设计选择**，不是"市场真理"，
   未来想放宽/收紧需新增策略版本，并重新回测验证。
4. **wave3 与主策略是两套独立体系**，主策略才是本文描述的多层漏斗。
5. 所有过滤层都遵循 **PIT（防未来函数）**：决策日只能看到决策日之前公开的数据。
